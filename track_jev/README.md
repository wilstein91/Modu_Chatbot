# track_jev — JEV 사용 버전

원칙(TypeSafe 공식 가이드): **판단은 Jev가, 결정은 코드가.** "이 질문을 넘겨야 하나?"를 Jev에게 직접 묻지 않는다. 판단 재료를 따로 묻고, 넘길지 말지는 코드의 진리표로 정한다.

| 파일 (예정) | 하는 일 | 만드는 단계 |
|---|---|---|
| `questions.py` | Jev에 보낼 질문·선택지·설명을 **한곳에** 모은다 (사람이 가장 자주 고치는 부분) | Step 4 |
| `router.py` | 한 번의 요청에 Choice(어느 카테고리?) + Noul(2기 훈련 규정에 관한 질문인가?) 등을 함께 보내고, 결과를 진리표로 판정 | Step 4 |
| `verifier.py` | 답변 문장마다 Choice(근거가 뒷받침 / 반대 / 말이 없음) — 숫자 가드레일이 못 잡는 "숫자 없는 지어내기"를 잡는 역할 | Step 7 |
| `agent.py` | `track_llm/agent.py`와 같은 그래프에서 판정·검증 노드만 Jev 버전으로 교체 | Step 8 |

## 진리표 초안 (Step 4에서 현준님이 확정)

| 범위 안? (Noul) | 카테고리 1위 확률 | 결정 |
|---|---|---|
| < 0.3 | — | 범위 밖 안내 |
| 0.3 ~ 0.7 | — | 운영진 이관 (애매) |
| > 0.7 | 높음 | 그 카테고리로 처리 |
| > 0.7 | 낮음 (1·2위 차이 작음) | 운영진 이관 또는 되묻기 |

> ⚠️ 0.7·0.3은 TypeSafe 문서가 권하는 **출발값**이다. 평가셋으로 재 보고 고친다. 몇 건에 맞춰 억지로 조정하지 않는다.

## 필요한 것
- `.env`의 `TYPESAFE_API_KEY` (이미 있음), 패키지 `typesafe-sdk`
- Jev 호출 테스트는 평가셋 문장을 TypeSafe 서버로 보낸다 → 첫 호출 전에 현준님께 확인받는다.
